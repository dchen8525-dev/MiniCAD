## 执行摘要

## 问题诊断

### 1. 交叉依赖网络

StepPreviewJsonExporter.java (14,682行) 形成了复杂的调用网络：

```
buildLegacyGeometry()
  ├─> buildEdgePayload()
  │     └─> curveEvaluator()
  │           └─> buildCurveEvaluator()
  ├─> buildPreviewFaceResult()
  │     ├─> toCylindricalFacePayload()
  │     ├─> toConicalFacePayload()
  │     └─> triangulateParametricFace()
  └─> collectStandaloneEdges()
        └─> toPolylineEdgePayload()

buildPmiPayloads()
  ├─> pointFromAnnotationPoint()
  │     ├─> pointFromStep() ✅ (已在StepPlacementTransformer)
  │     ├─> pointFromAnnotationOccurrence()
  │     └─> pointFromCurveCarrier()
  └─> toPmiPayload()
```

### 2. 无法简单提取的原因

#### 循环依赖示例
```java
// StepPreviewJsonExporter中的相互调用
buildGeometryForShells() {
    buildPreviewFaceResult(...)  // 调用面构建
}

buildPreviewFaceResult() {
    // 又需要buildGeometryForShells的数据
    buildGeometryForShells(...).faces()
}
```

#### 状态共享问题
- 多个方法共享builder、metadata、resolved等状态
- 提取后需要传递大量参数
- 可能破坏原有的优化和缓存机制

```java
public interface FaceBuilder {
    FacePayload buildFace(StepFaceEntity face);
}

    EdgePayload buildEdge(int edgeId);

```

#### 方案D：使用依赖注入
```java
public class StepGeometryBuilder {
    private final FaceBuilder faceBuilder;
    private final EdgeBuilder edgeBuilder;

    public StepGeometryBuilder(FaceBuilder faceBuilder, EdgeBuilder edgeBuilder) {
        this.faceBuilder = faceBuilder;
        this.edgeBuilder = edgeBuilder;
    }
}
```

- **时间成本高，但收益最大**
